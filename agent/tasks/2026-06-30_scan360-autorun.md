## Task
One command that makes the robot self-run a 360° in-place spin, capture frames,
and build the 360° map around it (PLY + BEV) — no manual second step.

## Input
Existing, hardware-proven pieces (06-29 live-run):
- `deepmap/rotate_scan.py` — self-spins 360° (12×30°) + captures fresh frames → `shots/`.
- `deepmap/build_map.py` — depth → metric project → 360° merge → `map_360.ply` (+ BEV
  in `--classify height`).
User decisions: (1) scope = single end-to-end orchestrator (spin→capture→build,
sequential); (2) default output = height mode → PLY + `map_360_bev.png`;
(3) spin was too slow / dwelled too long → **double wheel speed (hz 3000→6000)** and
**cut per-step settle (0.4→0.15s)** as the new defaults.

## Expected output
`python deepmap/scan360.py` (robot connected) →
- robot spins 360° capturing 12 frames into `deepmap/shots/`,
- then auto-builds `deepmap/output/map_360.ply` + `deepmap/output/map_360_bev.png`,
- single console summary (frames captured, points, floor/obstacle counts, paths).
Standalone `rotate_scan.py` / `build_map.py` keep working exactly as before.
Dry/offline test path works with no robot/camera.
