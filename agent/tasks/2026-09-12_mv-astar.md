## Task
MV module: A* path planning from the robot's current pose to a CM goal pose (roadmap L4), written in
C++ and exposed as a C API (shared library) that CM (Python) calls to paint the path on its GUI.

## Input
- CM goal JSON (`/api/ground/say` type `goal`): `matches[0] = {x, y, theta}` in world frame, m / rad.
- Scene JSON v2.0 (`simulation/room/scenes/*.json`): room width/length, object polygons, robot pose + hull radius.
- Roadmap `agent/description/robot_process_llm.md` L4: A* on occupancy grid -> primitives ROTATE/FORWARD/STOP.
- User decisions: C++ (not Python), consumed as an API by CM; CM draws the path.
- Compilers on this PC: MinGW.org g++ 6.3 (32-bit, used by RM tests) and Qt mingw1310_64 g++ 13 (64-bit,
  needed for a DLL loadable by 64-bit Python).

## Expected output
- `project/` builds `libmv` (static + shared), `mv_cli`, `test_mv`; `test_mv` passes.
- `python project/src/CM/app.py`: after a `goal` reply the UI draws the A* path + waypoints from the
  robot to the goal; `POST /api/plan` returns `{ok, path, waypoints, primitives, length_m}`.
- Unreachable goals are reported (`ok=false, reason`), never a path through an obstacle.
