## Implemented
1. **`depth-anything/src/stereo_ruler.py` refactor** (import-friendly, behavior of
   the CLI unchanged — regression-run on the saved pair, identical output):
   - `load_model(encoder, device)` — DA-V2 loaded ONCE, reusable across frames.
   - `load_rectify(path, size)` now returns a SimpleNamespace with `map_l, map_r,
     fb, fx, fy, cx, cy` (K taken from rectified P2 = the frame dense depth lives in).
   - `compute_metric_depth(left, right, calib, model)` → `(Z_m, valid, info)` —

     Z = f*B/disp) as one call. Raises RuntimeError on <10 golden points.
2. **`deepmap/stereo_walk_map.py`** (new): N stops × step-cm straight walk.
   Per stop: capture pair (`stereo_ruler.capture_pair`) → metric depth →
   back-project with rectified K (Y up = -(v-cy)Z/fy) → `level_to_floor`
   (floor-plane fit, ROTATION-ONLY + floor→Y=0 — no scaling, stereo is already
   metric) → place at dead-reckoned `Pose` → incremental PLY save.
   Drives between stops via `slam/robot_drive.drive_forward`. Final save:
   `icp_merge_clouds` (open3d) + `voxel_dedup`. Artifacts: shot_N_left/right.jpg,
   depth_N_m.npy, walk_map.ply in `deepmap/output/stereo_walk/`.

## Decisions
- Camera/calib resolution is **1280×720** (stereo_rectify.yml K), not the 640×480
  in the task Input; walk defaults to 720p and hard-fails on size mismatch.
- Depth lives in the RIGHT-rectified frame (DA-V2 runs on the right image), so
  back-projection uses P2 intrinsics and colors come from the rectified right.
- Floor leveling kept (camera tilts ~13°; without it pose.advance along world Z
  would not match horizontal travel) but scale removed — that was explore_map's
  heuristic the stereo ruler replaces.
